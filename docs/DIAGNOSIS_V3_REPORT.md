# 定向策略负结果：开发集机制诊断

本次没有新训练，也不改变 v2 结论。冻结提交 `b5eee45` 先于分析，脚本、来源和开发标签均有摘要；旧测试集没有进入本次诊断。运行：`.venv/bin/python scripts/diagnose_failure_v3.py verify`；界面：`.venv/bin/streamlit run diagnosis_dashboard.py`。

## 观察与决策

| 检查 | 实际结果 | 可以支持什么 |
|---|---|---|
| 完整分数 vs 低分质量 | Spearman 0.9878；前36重合32 | 当前候选排序主要受低分质量项影响 |
| 完整分数 vs 低分框数量 | Spearman 0.9524；前36重合31 | 低分框数量与排序高度关联 |
| 原型相似度范围 | 0.714–0.966；标准差0.041 | 全局特征原型在当前池上的区分范围较窄 |
| 开发集留组原型 AUC | 0.3951 | 不支持该相似度区分“存在低分可恢复漏检” |
| 质量项 / 完整分数 AUC | 0.5720 / 0.5514 | 当前开发数据上的判别力有限 |
| 开发集新增低分框 | 887框，55个新增匹配，832个未匹配 | 相对于现有标注，93.80%的新增低分框未命中新增目标 |
| 降阈值后剩余漏检 | 453/621个参考目标 | 仅降阈值不能恢复大部分目标；不能推断全部缺少proposal |

AUC 正例为具有低分可恢复目标的开发图，27正/9负，原型构建排除整组当前图；不同留组原型仍共享其余开发数据，故这里是描述性诊断，不报告独立样本显著性。测试集未用于阈值搜索、选择方法或训练。

| 可观察症状 | 竞争解释 | 最小干预 | 观察 | 验证状态与决策 |
|---|---|---|---|---|
| 定向没有优于随机 | 原型不判别 / 低分项噪声 / 学习能力限制 | 固定排序项分解和开发集留组检查 | 低分质量主导，原型AUC<0.5 | 支持前两项关联解释；不认定AP差值的因果归因 |
| 大量低分框 | 背景误检 / 类别错误 / 重复框 / 漏标 | 同类一对一参考匹配 | 832个未匹配 | 未独立人工裁决，不标为已确认背景或标签错误 |
| 453个目标仍未匹配 | 分辨率 / proposal / 类别 / 定位 / 标注 | 固定预测降阈值 | 未恢复 | 未对RPN或骨干做因果干预，不声称预测头不可修复 |

**决定：不再追加相似的采样训练对照。** 原型项当前没有足够判别证据；不能凭这次分析改权重后复用 v2 测试集追正结果。下一优先投入为独立视频挖掘项目，补足时序预算和视频级独立评测。标签问题另设独立质量审计研究。

简历描述：对真实道路检测采样负结果开展开发集机制诊断，分解原型与低置信度排序项并执行留组判别检查；发现完整评分与低分质量项相关系数0.988、原型AUC0.395，保留负证据并停止无依据的追加训练。

30秒介绍：我没有把定向采样包装成有效。三种子训练未支持其优于随机后，我冻结开发集诊断，发现排序几乎由低分项主导，原型不能有效区分目标失败。因此没有继续调参追结果，而是把后续投入转向视频级数据能力。

2分钟讲解：从v2等预算负结果出发，说明分数是相似度乘log低分质量；用秩相关和top36交集衡量两项改变候选名单的程度；开发集以低阈值新增同类匹配定义目标症状，排除当前整组建立原型；保留未匹配框，不将它们直接当标签错误；最后解释为什么这些关联不足以决定冻结骨干还是数据质量造成AP下降，以及为何停止训练。

最强质疑：“开发集上的分析是不是另一轮过拟合？”诚实回答：这是明确标记的探索性分析，使用已经见过的开发数据，不能证明新方法有效；没有新方法确认实验，也没有再用旧测试挑参数。
