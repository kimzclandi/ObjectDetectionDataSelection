# 面试与学习手册

## 领域地图

岗位的问题是：大量原始道路数据中，哪些数据应该进入训练，怎样可靠地生产这些数据，怎样知道它们确实有用？

核心对象是样本、标注、场景、数据版本、模型版本与资源预算。学习顺序：数据契约和切分 → 检测指标 → 采样对照 → 实际训练 → 任务恢复 → 性能瓶颈 → 多机扩展。

必须掌握：Python、SQL、数据结构、IoU/AP、数据泄漏、对照实验、幂等与失败恢复。进阶：主动学习、多模态质检、分布式执行、成本建模。暂时不必先做：全自动驾驶栈、自研 Spark/Flink、PB 级系统。

## 五个思维模型

| 模型 | 为什么成立 / 适用问题 | 失效边界 | 本项目的面试与工程用法 |
|---|---|---|---|
| 预算分配 | 标注资源有限，重点是单位预算价值 | 价值代理错误、同张数不同工时 | 解释为什么选 12 张；区分图片预算与人工预算 |
| 因果对照 | 结果变化可能来自随机性和额外训练 | 不同初始化、步骤或测试集 | 比较同初始化三策略，不夸大相对 warmup 增益 |
| 数据依赖图 | 同源样本可能泄漏到评测 | 文件名不能保证路线独立 | 描述分组哈希、重复阻断和剩余风险 |
| 按失败设计 | 任务中断和重试不可避免 | 外部副作用无法幂等、多个 runner 竞态 | 演示 running 恢复与唯一结果提交 |
| 切片与支持度 | 总分可能掩盖局部退化 | 小样本切片噪声大、门槛随意 | 总体 AP 与夜间召回同时报告，PASS 解释清楚 |

## 三个核心争议

**最不确定的样本是否最值钱？** 支持理由是暴露模型边界；反方指出异常图、重复场景和校准错误会占预算。前者假设不确定性与可学习信息相关，后者强调噪声与分布偏移。当前项目的不确定性组平均低于随机组，多样性只略高；局部证据不能证明某方法普遍优越。实践应保留随机组，检查入选样本，并用实验替代打分公式自信。

**自动标注能否降低成本？** 预标注能减少手动框选，但可能增加漏标检查和纠错。支持哪一派取决于候选框质量、审核标准和错误代价。当前项目仅输出真实检测器候选框，未测人时，所以没有降本共识可由本项目支持。下一步用独立人工审核集测质量和操作时间。

**何时引入分布式？** 并行支持扩展，调度也消耗时间。当前 Ray 单机扫描结果说明 240 张轻工作负载串行更快；不否定大规模或昂贵模型推理时的收益。应测计算/IO/调度占比、批大小、资源利用率和尾延迟，再选择系统结构。

## 30 秒回答

“我做了一个真实道路图像的数据闭环实验。先用 44 张图像微调检测头，再比较随机、不确定性和多样性三种策略，每组新增 12 张，跑三个随机种子。多样性平均只比随机高 0.045 个 AP 百分点，我没有把它包装成显著收益。系统保存了样本和模型版本，也验证了中断恢复及 Ray 的单机处理开销。”

## 深入追问与错误回答

| 追问 | 常见错误 | 应该说明的证据 |
|---|---|---|
| 你训练了什么？ | “训练了自动驾驶大模型” | 只训练 466,375 个 ROI 预测头参数，骨干冻结 |
| 为什么认为策略有效？ | “分数公式考虑了很多因素” | 等预算随机对照、配对差值和局限 |
| 为什么候选比基线好？ | “都是新增数据带来的” | 也多了训练步骤；三策略对比更干净 |
| 有没有标注泄漏？ | “代码里没用 test 就没有” | 候选契约、同组划分、图像和标签哈希、路线独立未验证 |
| PASS 是否意味着没退化？ | “九组都通过了，说明安全” | 夜间都退化了，只是没有超过演示门槛 |
| Ray 为什么更慢？ | “分布式应该更快” | 小工作量的调度成本、热缓存、单次计时范围 |

## 工程检查清单

- 输入格式、坐标约定、标签映射是否清楚？
- 一条图像能否追踪到源 revision、划分、采样决策、训练版本和评测？
- 测试图像是否与候选池分开？近重复和路线相关性怎样处理？
- 失败是否进入分母？空预测和没有 GT 的切片怎样处理？
- 重试会不会重复写结果？缓存是否识别图像、权重和配置变化？
- 结果是否与同预算随机组比较？有没有额外训练步数混杂？
- 报告中的每个数字能否指回 JSON 和代码？

## 最小实践任务

先运行 `driving-data verify`，打开工作台的一个夜间漏检样本。记录三种可能原因，明确哪些只是猜测。然后只在 dev 集设计“分辨率变化”的诊断实验，预先写下要比较的指标与失败判据；在任何运行前解释为什么不能直接使用 test 选择分辨率。
