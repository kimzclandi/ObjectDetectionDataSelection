# 架构与工程权衡

## 数据契约优先

图像实体保存在独立文件中，Parquet 保存元数据供 DuckDB 扫描，JSON 保存小规模可审计证据。生产系统通常还需要对象存储、索引服务、访问控制与数据生命周期管理；本项目不以本地目录冒充这些能力。

接入并发下载固定 revision 的 240 个对象，下载到 `.partial` 后原子替换。索引文件有预先固定的 SHA-256；图像解码、尺寸匹配、框有效性、去重和分组检查全部通过才写完整 manifest。失败输入落入隔离错误清单，整批不发布半成品。暗图不自动删除，因为夜间恰好是目标切片。

## 推理恢复的语义

任务 key 包含样本 ID、图像字节哈希、模型权重哈希和推理配置。平台、库版本及设备变化会导致缓存失效。

1. 使用 OS 非阻塞排他锁，禁止两个 runner 共享同一日志库。
2. SQLite WAL 日志记录 pending/running/succeeded/failed 与尝试次数。
3. 推理前提交 running；结果和 succeeded 在同一事务提交。
4. 进程中断后重新把 running 放回 pending。
5. 已完成任务经图像校验后复用；异常任务最多在本次调用尝试两次。

这是 **至少一次计算、每个内容 key 最多一条已提交结果**，不是“恰好一次执行”。模型可能在提交前被重复计算，写入幂等避免重复产物。永久错误在重试用尽后中止整轮，不静默减少评测分母。

限制：单机单 runner、共享本地文件系统。没有分布式租约、心跳、跨机对象存储、按错误类型动态退避或自动 GPU 调度。`fcntl` 锁面向 macOS/Linux，Windows 未支持。

## 采样策略

不确定性代理：取最多 20 个分数最高的检测，对每个置信度 p 算二元熵 `H(p)=−p log(p)−(1−p)log(1−p)`，再除以 `log(2)` 归一化并平均。它依赖模型的候选输出，不能可靠发现“自信漏检”；后 NMS 分数也不是严格校准的认知不确定性。

零检测图像被赋予探索分数 1：这是明确策略，不是判断图像必然困难。纯负样本和真正漏检可能混在一起。

多样性策略贪心选择：`0.5 × 熵代理 + 0.5 × 与已选图像的最小余弦距离/2`。第一张只看熵；每个前缀组最多一个样本。骨干特征来自整张图像，可能偏重背景，未证明与训练价值线性相关。当前没有使用来源场景配额，避免把上游人工标签当作免费信息。

随机组也得到同一候选池；每个训练种子对应一个随机样本集。不确定性/多样性在没有并列分数时可跨种子选中同一批图，变化主要来自训练随机性。

## 为什么不把 Ray 放进每一步

当前神经推理串行即可跑通 240 张图像。Ray Data 仅用于独立图像扫描的实测；输出逐 ID 与串行实现比较相等。

本次串行约 532 图/秒，Ray 1/2/4 worker 约 133/465/480 图/秒，Ray 初始化另需约 4.39 秒。工作量太小，调度与序列化开销会超过并行收益。只跑一次且文件缓存已热，不能据此预测大数据规模。

扩展时应先测量解码、模型、读写与调度各自占比，再决定批大小、actor 复用、分区布局、对象存储和资源约束。训练与推理是否迁移到 Ray，应由实际瓶颈决定。
