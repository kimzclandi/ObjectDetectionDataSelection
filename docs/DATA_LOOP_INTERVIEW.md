# 数据闭环研发：面试与现场验收

先读本轮结果报告，再用这份手册检查自己是否能独立解释。AI 辅助完成的代码不等于本人已经掌握；下列练习未作答前，不登记为“已掌握”。

## 领域地图

数据闭环解决的不是“怎样产出更多数据”，而是如何把有限标注和训练预算转化为可验证的模型改善。主干为：数据/标签契约 → 固定基线 → 开发失败 → 可检验假设 → 无标签选样 → 标注获取 → 匹配训练 → 隔离评测 → 决策。评测隔离与随机对照是必会；梯度/影响函数选样、概率校准、跨域泛化是进阶；当前暂不需要堆分布式平台。

输入是开发图像和标签、无标签池、固定模型、预算；输出不仅是入选 ID，也包括拒绝假设或维持原策略的决策。离线 AP 与部署安全、人工成本、时效性是不同问题。

## 五个核心思维模型

| 模型 | 为什么成立、适用处 | 失效边界与面试用法 |
|---|---|---|
| 反事实比较 | 同一初始模型，只改变数据政策，配对比较能减少其他因素混淆 | 若训练步数、评测或优化器同时变化，不能归因；现场指出 random−seed_only 和 targeted−random 分别回答什么 |
| 测量先于优化 | 如果标签、分母、图像输入无效，分数增加没有明确意义 | 指标不能代表全部业务价值；用 VLM blank/mismatch 说明敏感性与正确性不同 |
| 症状不等于根因 | 漏检同时可能来自分辨率、提议框、分类分数、标签或域偏移 | 单一干预不能定位全部原因；解释阈值干预为何只验证已有低分可匹配框 |
| 相关单位决定不确定性 | 同场景变体/同驾驶段共享因素，按对象独立抽样会低估区间 | 前缀代理可能漏掉真正会话相关性；说明组bootstrap仍不等于路线独立 |
| 闭环是可拒绝的决策系统 | 没有不收益或退化时的停止条件，会变成追分流程 | 过窄门禁可能错杀局部收益；用预设主指标、负结果与非目标退化解释下一步 |

## 三个核心争议

1. **不确定性还是多样性？** 不确定性倾向决策边界，多样性减少冗余。前者假定不确定来自可学习样本而非噪声；后者假定特征距离对应训练价值。本项目旧实验未证明稳定优胜，本轮原型策略也必须接受随机对照反证。实践中固定预算检验，不能引用一般经验代替实际效果。
2. **主动采样收益用何种预算衡量？** 图像数易控制，但框数、难度和人工秒数更贴近成本。当前证据只支持同样12图，不能推出降本。生产中应同时记录标注时长、返工和质量；这尚未验证。
3. **先修模型还是先补数据？** 能定位但低分的错误可能适合头部微调；无候选框/尺度限制更可能需要分辨率、提议网络或骨干改变。标签错误应先修标签。当前阈值检查只缩小解释空间，不能证明补数据必然有效；必须先做最小干预，再选投入路径。

以上是实验设计上的权衡，不是声称该领域已经对某一种策略形成普遍共识。

## 30秒介绍

我做的是一个可审阅的数据策略实验：从真实检测器的开发集漏检提出选样假设，用不读取池标签的规则选择12张图，与随机新增和仅继续训练比较。三组共用初始模型、112步和三个种子；120张新增评测图排除旧实验图像组，训练全部完成后统一评测。本轮定向比随机平均低0.634 AP点，区间跨零；我保留这个负结果和非目标退化，不把可解释的选样包装成已验证收益。

## 2分钟技术讲解

先固定 MobileNetV3 Faster R-CNN 的 warmup，只微调 ROI predictor。开发集检查发现一些目标在0.05分数阈值能匹配、0.5不能匹配；这个事实不等于根因，但给出可检验的方向。我对具有这种失败的开发图构建单位化全局特征原型，池端用像素推理得到的特征和低分预测质量排序，不读池真值。

标注预算按12图匹配，种子101/211/307。seed-only增加重复训练槽位，使所有组112步；这能把“继续训练”与“加入新图”分开。入选名单、源代码、权重、数据哈希和参数先提交。九组训练完成才评测新120组，不早停、不选checkpoint。

主指标是定向相对随机的平均AP差，并按前缀组做配对bootstrap；目标切片由共同基线定义一次，再看其召回和补集退化。最后报告实测结果，即使策略没赢。我的边界是小规模同源公开数据、仅训练预测头、没有人工成本或生产安全验证。

## 最强质疑与诚实回答

- **这是不是又一种不确定性排序？** 有相似之处。本轮加入开发失败原型，但没有组件消融，不能把差异独立归因于原型；若原型相似度几乎恒定，策略可能主要由低分框数量驱动。
- **你真的知道错误原因吗？** 不知道全部。只验证某些框在低阈值可匹配；FP激增说明阈值恢复不是一个可直接上线的修复方案。
- **为什么不是全模型训练？** 本地资源下用固定骨干使实验便宜且变量可控，但也限制了可修复的表征错误。不能写成端到端自动驾驶感知训练。
- **120图足够证明收益吗？** 只支持该小样本同源设置下的证据；三个seed与组bootstrap都不解决真实路线相关性、分布漂移和预训练污染。
- **没有赢还算闭环吗？** 若假设、对照和失败分析可信，拒绝无效策略就是闭环决策；但不能因此宣称算法优于现有方法。
- **你亲自做了什么？** 应如实说明 AI 辅助代码/报告，能够现场解释实验假设、实现和证据；不能虚构独立实现经历。

常见错误回答：“测试多所以算法可信”“AP提高就是数据价值”“低置信度就是难例”“公开标注等于人工复核”“三个seed等于三个独立数据集”。

## 工程现场检查清单

核对模型/数据/标签/缓存身份；确认采样函数没有池标签字段；数出每组112步和12个新增唯一ID；说明控制组为何重复旧图；检查失败分母；定位源协议版本；从原始预测重算一个TP/FP与AP；说明resume保存了什么；指出当前分组和指标无法保证的事情。

核心代码：`failure_loop.py` 的 `diagnose`、`rank_pool`、`schedule`、`train_run`、`metrics`、`analyze`；相邻模块 `evaluation.py::match_objects/coco_metrics`。输入RGB是 `float32[3,H,W]`，标签框是 `[N,4]`、类别 `[N]`，骨干池化特征 `[256]`，输出是框/类别/置信度。冻结参数与 `.eval()` 不同：前者控制梯度，后者影响BN/Dropout行为。
