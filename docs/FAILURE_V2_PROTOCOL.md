# 失败驱动选样 v2：事前协议与复现

## 新增问题，而非重复旧对照

旧实验已比较 random / uncertainty / diversity 三种策略和三个种子，随后增加 seed-only 匹配步数对照；测试集曾被查看。v2 保留这些历史证据，研究新的具体假设：**接近开发集低置信度可恢复漏检的图像，是否比随机图像提供更多训练价值？** 评测改用新的 120 个前缀组，排除全部旧 240 图所属组。

`37eba66` 在本轮训练前冻结代码、数据 manifest、开发失败诊断、实际入选名单和协议。模型仍用旧实验的共同 warmup 权重，只训练 466,375 个 ROI 预测头参数。不是全量检测器训练，也不是 VLM 训练。

## 假设如何来自失败

固定 warmup 模型、同一开发集、同一组预测框，将匹配分数阈值从 0.5 降到 0.05，仍要求同类、IoU≥0.5、一对一匹配。保存每个开发图的 TP/FP、被恢复的 GT 索引，而不是只贴“感知失败”标签。

竞争解释包括分类置信度/域偏移、标签歧义或漏标、低分辨率与冻结特征限制。阈值干预能验证某些目标在现存预测中已有可匹配框，但不能定位网络内部原因。阈值降低也带来 FP；AP 原本使用 ≥0.05 的完整预测，因此这个诊断并不提高 AP。

对至少有一个“低阈值命中、高阈值未命中”目标的开发图，平均其单位化 256 维骨干特征，再单位化得到失败原型。无标签候选池评分：

`score(x) = max(0, cos(feature(x), failure_prototype)) × log(1 + Σ p(1-p))`

求和只包含 0.05≤p<0.5 的预测。没有真实框、天气、时段或 oracle 标签输入选样函数。按评分取前 36 张，分别用 101、211、307 随机抽 12 张，每前缀组最多一张。随机组在全部 101 张池中抽 12 张。完整排序、分解分数和入选 ID 先冻结，之后才允许训练路径读取公开标注；这是模拟标注获取，不是已完成人工标注。

该策略可能失败：特征相似不等于梯度价值，低置信度框可能是背景噪声，近似相同的全局特征会使评分退化为预测数量指标。没有做组件消融，不能单独归因于原型这一项。即使负结果也报告，不继续改公式直到胜出。

## 控制变量

- 三组共同 warmup、候选池、结构、优化器、学习率 0.005、momentum 0.9、weight decay 0.0005、CPU、batch=1。
- 定向与随机：44 张 seed +12 张新增，各两个 epoch，共 112 步。
- seed-only：44 张 seed +12 个确定性重复槽位，各两个 epoch，同样 112 步，不消耗新标注。
- 各组都新建优化器，同一 seed 控制采样/训练随机性；骨干参数和 BN 统计量冻结，只更新 ROI predictor。
- 三种子全部报告；只保存最终步模型作评测，不早停、不挑 checkpoint，不根据测试选择策略。
- 九个 checkpoint 全部完成后才运行新测试集推理与指标。原 warmup 在新测试集上的评测也在此后进行。

新增预算按图像计，并不匹配框数量或人工秒数。需要同时读 targeted−random（选择收益）和 random−seed_only（新图相对重复旧图的收益）；相对 warmup 的变化还混有额外训练收益。

## 数据隔离与许可

固定 BDD100K 第三方镜像 revision 和 index SHA-256 沿用旧数据卡。新测试按 `digest(['fresh-test-v2', filepath])` 排序，从不属于旧组的图像中取 120 张。不按标签、质量、错误筛选。重复检查仅根据像素，排除字节相同或 dHash 距离≤8 且 16×16 灰度 MAE<5 的图像。排除记录全部保存。旧数据集合也单独做相同跨集检查。

前缀是保守的分组代理，不代表经证实的路线、司机或视频会话。同源重划分不是官方 BDD benchmark，也不能排除预训练数据污染。数据按原 BDD100K 教育研究许可使用，模型按官方来源许可使用；仓库不分发道路图片、原始标注或模型权重。下载和训练无需付费 API 或云资源。

## 指标与统计

主指标：全部三种子的 `AP(targeted)−AP(random)` 平均值，COCO IoU 0.50:0.05:0.95、当前七个映射类别。AP为0–1；乘100后是AP百分点评述。

关键失败切片事前定义为 **warmup 在0.05命中但0.5未命中的GT集合**。这个集合只定义一次，不能随候选模型移动。报告其0.5阈值召回、补集召回、时段切片、总体精确率、支持数量和成本。切片按GT统计但不把每个GT当独立统计样本。

主区间使用200次前缀组配对bootstrap，每次各模型与各种子共用相同抽样组。对每个重采样集合重新计算每个模型的AP，再求三种子的配对差平均。它是条件于这三个训练结果的数据不确定性描述，不包含完整训练随机性；同时报告每个seed及种子标准差。200次、120组的小实验区间精度有限，不用于安全认证。未挑最优seed或有利切片。

## 运行与恢复

从仓库根目录使用已有 `.venv`：

```bash
# 初次准备新实验；重复运行只接受内容一致的manifest
PYTHONPATH=src .venv/bin/python -m driving_data.failure_loop prepare
# 已有冻结协议时不要再运行 freeze
PYTHONPATH=src .venv/bin/python -m driving_data.failure_loop run
PYTHONPATH=src .venv/bin/python -m driving_data.failure_loop analyze
.venv/bin/python scripts/verify_failure_v2.py
.venv/bin/python -m pytest -q
.venv/bin/streamlit run dashboard.py --server.port 8514
```

从零复现需要先按原 README 准备旧240图并生成/恢复共同 warmup。新 manifest 保存全部图像和标签摘要。若缺少相同 warmup，其生成命令与旧 `training.json` 的配方均保留。权重必须与协议摘要一致，不可悄悄换初始模型。

执行代码、依赖、模型、图像、标签、manifest、诊断、入选名单漂移时拒绝继续。训练每14步原子保存模型/优化器/RNG，恢复后核对配方。推理逐图原子保存，异常另存错误记录并中止完整评测，不能从分母删掉。已完成结果核对后复用，不覆盖；意外损坏必须保留原文件并显式调查。参考报告在同目录不可替换。

## 必须保留的工程边界

缓存校验和错误日志是可靠性手段，不是密码学隔离。池标签仍在同一机器；函数契约防止正常代码路径误读，不防恶意文件访问。根因队列没有人工确认。算法收益必须由结果而非测试数量决定。
